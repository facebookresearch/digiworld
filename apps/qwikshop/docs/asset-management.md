# Asset Management in Qwikshop App

This document outlines how assets are managed in the Qwikshop application, utilizing the shared asset management package.

## Architecture Overview

The Qwikshop app uses a hybrid approach for asset management:
1. Static assets (bundled with the app)
2. Dynamic assets (downloaded and cached)

### Image Map Generation

Static assets are managed through an auto-generated image map:
- Location: `src/generated/imageMap.ts`
- Generated by: `scripts/generateImageMap.js`
- Updates: Run `npm run generate-image-map` to update

## Asset Types

### 1. Product Images
- Main product image
- Gallery images (multiple views)
- Stored in: `src/assets/images/products/{productId}/`
- Naming: `main.jpg`, `gallery_1.jpg`, `gallery_2.jpg`, etc.

### 2. User Avatars
- Static avatars (bundled)
- Custom avatars (uploaded)
- Stored in: `src/assets/images/avatars/`
- Naming: `user_{1-50}.jpg` for static avatars

## Implementation Guide

### 1. Static Asset Resolution

For bundled assets (products, static avatars):

```typescript
import { resolveAssetPath } from '@shared/asset-management/utils/resolveAsset';

// Product main image
const { localPath: mainImagePath } = await resolveAssetPath({
  appName: 'qwikshop',
  entityType: 'product',
  entityId: productId,
  assetType: 'image',
  imageConfig: { type: 'main' }
});

// Product gallery image
const { localPath: galleryImagePath } = await resolveAssetPath({
  appName: 'qwikshop',
  entityType: 'product',
  entityId: productId,
  assetType: 'image',
  imageConfig: { type: 'gallery', index: 1 }
});

// Static avatar
const { localPath: avatarPath } = await resolveAssetPath({
  appName: 'qwikshop',
  entityType: 'user',
  entityId: userId,
  assetType: 'avatar',
  avatarIndex: 5  // Uses static avatar #5
});
```

### 2. Dynamic Asset Resolution

For user-uploaded content:

```typescript
// Custom user avatar
const { localPath } = await resolveAssetPath({
  appName: 'qwikshop',
  entityType: 'user',
  entityId: userId,
  assetType: 'avatar'
});
```

### 3. Image Components

Reusable components for common use cases:

```typescript
// ProductImage.tsx
import { resolveAssetPath } from '@shared/asset-management/utils/resolveAsset';
import { Image } from 'react-native';

export async function ProductImage({ productId, type = 'main' }) {
  const { localPath } = await resolveAssetPath({
    appName: 'qwikshop',
    entityType: 'product',
    entityId: productId,
    assetType: 'image',
    imageConfig: { type }
  });

  if (!localPath) {
    return <FallbackImage />;
  }

  return <Image source={{ uri: localPath }} />;
}
```

## Best Practices

1. **Performance**
   - Preload critical images (e.g., first few product images in a list)
   - Use appropriate image sizes and quality settings
   - Implement progressive loading for galleries

2. **Error Handling**
   - Always provide fallback images
   - Handle loading states appropriately
   - Log asset resolution failures for monitoring

3. **Maintenance**
   - Regularly run image map generation
   - Clean up unused assets
   - Monitor asset cache size

## Common Issues and Solutions

1. **Missing Images**
   ```typescript
   // Always handle null paths
   const { localPath } = await resolveAssetPath(config);
   if (!localPath) {
     console.warn(`Missing image for product ${config.entityId}`);
     return <FallbackImage />;
   }
   ```

2. **Image Map Updates**
   - If new images aren't showing up, regenerate the image map:
     ```bash
     npm run generate-image-map
     ```

3. **Cache Management**
   - Clear cache if facing persistent issues:
     ```typescript
     await AssetManager.getInstance().clearCache();
     ```
